## 1. Library

**Lingui v5** (`@lingui/core`, `@lingui/react`, `@lingui/core/macro`,
`@lingui/react/macro`, `@lingui/cli`, `@lingui/conf`, `@lingui/detect-locale`,
`@lingui/format-po`). No second translation system exists; do not add one.

- Config: `lingui.config.ts` (repo root)
  - `sourceLocale: 'en'`
  - `locales`: all of `SUPPORTED_LANGUAGE_CODES` from `packages/lib/constants/locales.ts`
  - **One single catalog** shared by web UI **and** email templates:
    `packages/lib/translations/{locale}/web.po` (PO format, `lineNumbers: false`)
  - Catalog `include`: `apps/remix/app`, `packages/ui`, `packages/lib`, `packages/email`
- Commands (root `package.json`):
  - `npm run translate:extract` → `lingui extract --clean`
  - `npm run translate:compile` → `lingui compile` (emits `web.mjs` per locale)
  - `npm run dev` runs `translate:compile` first; `web.mjs` files are gitignored
    (`packages/lib/translations/.gitignore`)
- Source macros used across the repo:
  - `<Trans>string</Trans>` / `<Trans>str {var} str</Trans>` (JSX, `@lingui/react/macro`)
  - `` t`string` `` (TS, `@lingui/core/macro`)
  - `` msg`string` `` + `_(msg`…`)` for non-component strings
  - `i18n.date(...)` / `i18n.number(...)` for locale-aware formatting

## 2. Catalog layout

```
packages/lib/translations/
  {locale}/web.po      # THE catalog (web + email share it)
  en/web.po            # source of truth (≈3,200 msgids)
  fr/web.po            # exists upstream; Crowdin community French (fr-FR-ish),
                       # ~94% complete (189 empty msgstrs as of Phase 4 start).
                       # Phase 4: 3,227 msgids, 100% translated (374 machine-
                       # translated ids logged in REVIEW-NOTES.md), glossary-
                       # normalized to fr-CA.
  de/ es/ it/ ja/ ko/ nl/ pl/ pt-BR/ zh/ ...  # other upstream locales
  sq/                  # legacy dir NOT in SUPPORTED_LANGUAGE_CODES
```

- Compiled catalogs are loaded via dynamic `import('translations/{locale}/web.{po|mjs}')`
  (`NODE_ENV=development` → `.po`, else `.mjs`) in:
  - `packages/lib/utils/i18n.ts` — `dynamicActivate(locale)`
  - `packages/lib/client-only/providers/i18n-server.tsx` — `getI18nInstance(lang)` /
    `allI18nInstances` (one preloaded `setupI18n` instance per supported locale)
- `crowdin.yml` mirrors the catalog path (`packages/lib/translations/{locale}/web.po`).

## 4. Web locale detection (as shipped by Phase 4)

Order of resolution, server-side (`apps/remix/app/entry.server.tsx`):

0. **`?lang=` query-param override** (added Phase 4, D-022) — validated
   against `supportedLangs`; beats the cookie for that request so hreflang
   alternates (`/ ?lang=en|fr`) render locale-correct HTML for crawlers;
   the root loader serializes the choice into the `lang` cookie.
1. **`lang` cookie** (`apps/remix/app/storage/lang-cookie.server.ts`,
   `createCookie('lang', { path: '/', maxAge: 2y, httpOnly, secure: prod })`)
2. **`Accept-Language` header** — `extractLocaleData({ headers })`
   (`packages/lib/utils/i18n.ts`): parses **base language only**
   (`fr-CA` → `fr`), must be in supported list, first valid wins
3. **Fallback** `sourceLang` = `'en'`

Then `dynamicActivate(lang)` + `<I18nProvider>` wrap the server render;
`apps/remix/app/root.tsx` sets `<html lang={lang}>` and re-serializes the cookie
on every response. The resolution helper `getLocaleFromRequest(request)`
(`lang-cookie.server.ts`) is shared by `entry.server.tsx` and the root loader.

Client hydration (`apps/remix/app/entry.client.tsx`):
`detect(fromHtmlTag('lang')) || 'en'` → `dynamicActivate`.

**Switcher UI (Phase 4 shipped):** two widgets.
- `LanguageSwitcherDialog` (`packages/ui/components/common/language-switcher-dialog.tsx`, command palette) → `dynamicActivate(lang)` + `POST /api/locale`, wired into the authenticated user menu (`org-menu-switcher.tsx`).
- **`LanguageSwitcher`** (new, `packages/ui/components/common/language-switcher.tsx`, compact dropdown showing the active locale) → `POST /api/locale` (same validated cookie route) then reloads the page. Ships in the **public header + footer** (`app-footer.tsx`), **auth pages** (`_unauthenticated+/_layout.tsx`), and the **authenticated app header + footer** (`_authenticated+/_layout.tsx`). It strips `?lang=` before reloading so the cookie choice wins for the session.

**URL strategy: none.** Cookie-based switching retained (upstream 100 %
cookie-based; no `/fr/*` routes) — spec fallback clause applied, tradeoff
recorded in DECISIONS.md D-022.

## 5. Email locale (as shipped by Phase 4)

- Per-document email language lives on **`DocumentMeta.language`**
  (`packages/prisma/schema.prisma`, `String @default("en")`); the sender
  sets it in the envelope editor Settings dialog (default unset).
- `getEmailContext()` (`packages/lib/server-only/email/get-email-context.ts`)
  computes:
  `emailLanguage = meta.language (DocumentMeta.language) || organisationGlobalSettings.documentLanguage`
- All email handlers call `renderEmailWithI18N(template, { lang: emailLanguage, branding })`
  (`packages/lib/utils/render-email-with-i18n.tsx`) → `getI18nInstance(lang)`
  → falls back to `sourceLang` (`'en'`) when the code is unsupported.
- **There is no per-recipient or per-user `locale` column in the schema.**
  The effective chain is therefore:
  `DocumentMeta.language → org settings documentLanguage → 'en'`.
  The spec's “recipient → owner → en” intent requires a schema addition and
  is deferred to Phase 5 (compliance workstream) — decision D-024, logged in
  REVIEW-NOTES.md.
- Every react-email template renders through the shared Lingui catalog, so
  fr-CA coverage of email strings is 100 % of the catalog. FROM name stays
  `NorthSign` in both languages (brand constant, not translatable).

## 6. Formatting (as shipped by Phase 4)

- Dates/times/numbers render through **Lingui `i18n.date()` / `i18n.number()`**
  (Intl under the hood, driven by the active locale) — e.g. data-table cells
  already use `i18n.date(...)`; fr-CA gets 24 h clock and `AAAA-MM-JJ`
  date order automatically.
- `DocumentMeta.dateFormat` (per-document, e.g. `yyyy-MM-dd hh:mm a`) is a
  luxon-style string the **user chooses per document**; it is intentionally
  NOT locale-switched during Phase 4 (user preference wins over locale
  default — decision D-025).
- **PDF text localized** (D-025): the signature dictionary reason is now
  `docI18n._(msg\`Signed by ${APP_NAME}\`)` → « Signé électroniquement par
  NorthSign » for fr documents, and the rejection stamp title is passed
  through the same instance (« DOCUMENT REFUSÉ »), keyed off
  `DocumentMeta.language` in `seal-document.handler.ts`.
- Emails use react-email + Lingui `Trans`; locale-specific formatting flows from
  the same catalog/`i18n.date` utilities.
- Currency: Phase 6 (billing) will use `Intl.NumberFormat` CAD via
  `i18n.number` — infrastructure is already locale-aware; no code needed
  until then.

| download | **télécharger** | — |
| sender | **expéditeur** | — |
| owner | **propriétaire** | — |
| draft | **brouillon** | — |
